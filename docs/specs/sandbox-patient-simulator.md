## 1. ארכיטקטורת המערכת וה-Flow

### 1.1 למה זה לא צ'אט

ההבדל בין הפיצ'ר הזה למנטור הקיים הוא לא הפרומפט.
המנטור הוא מודל שמנסה לעזור.
הסימולטור חייב להיות מודל ש**מסרב לעזור**, ומחזיק מצב שהתלמיד צריך לפרוץ.

מזה נגזרת כל הארכיטקטורה: **המצב חי בקוד, לא במודל.**
המודל מקבל את המצב כעובדה ומשחק לפיו.
הוא לא מחליט מתי הראפור עלה ולא מחליט מתי למסור את הפרט הקריטי.
זה מה שמונע את כשל הקריסה, שבו המטופלת הווירטואלית נשברת בתור השני ומודה בכל, והתרגיל מאבד ערך.

### 1.2 User Flow מקצה לקצה

```
[1] כניסה
    ספריית הקורס ← שיעור "פירוק הכללות" ← כרטיס "תרגול חי"
    שער: paid_customer + השיעור הנדרש הושלם + מכסה יומית לא נוצלה

[2] חדר הכנה (briefing)
    מי המטופלת · מה המשימה (מיומנות יחידה) · תקציב תורות · מה נמדד
    התלמיד חייב לדעת מראש על מה הוא נבחן. זו למידה, לא מבחן פתע

[3] סשן (turn loop)
    המטופלת פותחת ← התלמיד מגיב ← הערכה ← עדכון מדדים ← תגובת המטופלת
    מדי-מצב חיים על המסך: ראפור · התנגדות · עומק · פירוט
    כפתור "רמז" זמין, עולה בניקוד

[4] סיום, באחת משלוש דרכים
    ✅ הצלחה  — תנאי ההצלחה של התרחיש התקיימו
    ⏱ תקציב  — התורות נגמרו
    ❌ קריסה  — הראפור ירד מתחת לסף והמטופלת מתנתקת

[5] תחקיר (debrief)
    תמליל מוער תור-תור · כרטיס ציון · "השורה שהייתה עובדת" לשלוש הנקודות החלשות
    כפתור: שחק שוב מתור N

[6] שמירה
    סשן נשמר · XP ללוח המובילים · התקדמות נרשמת
```

הנקודה הפדגוגית בשלב 5: הערך אינו בציון.
הערך הוא ב**ניסוח החלופי** שהתלמיד מקבל בדיוק על המשפט שהוא כתב.
בלי זה זה משחק, לא הכשרה.

### 1.3 מכונת המצבים

**מצבי סשן:**

```
briefing → in_session → ended(success|budget|collapse) → debriefed → archived
```

מעבר מ-`in_session` ל-`ended` הוא **בצד השרת בלבד**.
לקוח לא יכול להכריז על הצלחה.

**לולאת התור, בתוך `in_session`:**

```
awaiting_student
   ↓ התלמיד שולח
validating        ← אורך, קצב, מכסה, חסימות קשיחות. בקוד, בלי מודל
   ↓
evaluating        ← קריאה 1: שופט. מחזיר JSON נוקשה
   ↓
applying          ← הקוד מחיל דלתאות, בודק פתיחת עובדות, בודק תנאי סיום
   ↓
acting            ← קריאה 2: שחקן. מקבל מצב מעודכן, מחזיר שורת דיאלוג בלבד
   ↓
awaiting_student
```

הסדר קריטי.
השופט רץ **לפני** השחקן, ולכן השחקן משחק לפי מצב שכבר נקבע.
אם משחקים קודם ושופטים אחרי, המודל כבר התחייב לתגובה והשיפוט מתיישר אליה.

### 1.4 מה נשמר בכל תור

שלוש שכבות, ורק אחת מהן גדלה:

| שכבה | גודל | גדלה עם השיחה? | איפה |
|------|------|----------------|------|
| פרומפט מערכת + הגדרת התרחיש | ~1,800 טוקן | לא | נשלח עם `cache_control: ephemeral`, כמו שכבר נעשה ב-`gemini-mentor` |
| `session_state` | ~250 טוקן | לא. גודל קבוע | JSONB בשורת הסשן |
| חלון גלגול | ~600 טוקן | **לא**. חסום | 6 התורות האחרונים + תקציר מתגלגל |

**שיטת החלון:** שומרים מילולית רק את 6 התורות האחרונים.
כל 6 תורות מייצרים תקציר דחוס של מה שנפל מהחלון, בקריאה זולה אחת, ודורסים את התקציר הקודם.
התקציר מוגבל ל-80 מילים ומכיל רק שלושה דברים: מה נמסר בפועל, מה התלמיד ניסה ונכשל, ומה הטון.

התוצאה: **עלות התור אינה עולה לאורך הסשן.**
שיחה של 12 תורות עולה בערך כמו שיחה של 4.
זו ההגנה היחידה שעובדת בסימולטור, כי כאן שיחות ארוכות הן לא חריג אלא ברירת המחדל.

מה **לא** נשלח למודל אף פעם: התמליל המלא, מדדי הניקוד ההיסטוריים, עובדות נעולות שטרם נפתחו.
עובדה נעולה שנשלחת למודל תידלף. תמיד.

### 1.5 תקציב וצפי עלות

חישוב לסשן מלא של 12 תורות:

| רכיב | מודל | קלט | פלט | עלות |
|------|------|-----|-----|------|
| שחקן × 12 | Sonnet | 400 טרי + 1,800 מטמון | 120 | ~$0.036 |
| שופט × 12 | Haiku / Gemini Flash | 500 | 150 | ~$0.004 |
| תקציר × 2 | Haiku | 700 | 80 | זניח |
| תחקיר × 1 | Sonnet | 3,000 | 900 | ~$0.022 |
| **סה"כ** | | | | **~$0.062 ≈ ₪0.24** |

100 סשנים בחודש = **כ-25 ₪**.
זה נכנס בנוחות מתחת ל-`AI_MONTHLY_CAP_ILS` הקיים, אבל **רק כל עוד החלון חסום**.
בלי חסימת החלון, סשן של 20 תורות עולה פי שלושה ומעלה.

מגבלות קשיחות שנכנסות לקוד:
- `turn_budget` פר תרחיש, 10-14
- 600 תווים להודעת תלמיד
- 3 סשנים ליום למשתמש
- אותה תקרת ₪ חודשית משותפת עם שני המנטורים. מעליה, הפיצ'ר **נחסם** ולא עובר למודל חלש. מטופלת מדגם חלש היא תרגול שמלמד דפוסים שגויים, וזה גרוע מאין תרגול

### 1.6 התרשים המלא

```
דפדפן (nlp-game-master.html)
   │  JWT אמיתי של המשתמש
   ▼
Edge Function: sim-turn          verify_jwt: true
   ├─ 1. שער: role, מכסה יומית, תקרת ₪, בעלות על הסשן
   ├─ 2. טוען sim_session + sim_scenario
   ├─ 3. בדיקות קשיחות בקוד (regex, אורך, חזרתיות)
   ├─ 4. קריאת שופט      → JSON נוקשה
   ├─ 5. החלת דלתאות, פתיחת עובדות, בדיקת סיום   ← כל ההחלטות כאן
   ├─ 6. קריאת שחקן      → שורת דיאלוג
   ├─ 7. כתיבה: sim_turns, sim_sessions, ai_chat_usage
   └─ 8. מחזיר: {reply, metrics, unlocked, status, turns_left}

Edge Function: sim-debrief       נקראת פעם אחת בסיום
   └─ קריאת Sonnet יחידה על כל התמליל → כרטיס ציון + ניסוחים חלופיים
```

שתי פונקציות ולא אחת, כי לתחקיר פרופיל עלות ואיטיות אחר לגמרי.
ערבוב שלהן הופך כל תור לתור יקר.

## 2. מבנה הנתונים

### 2.1 טבלאות

```sql
-- ── תרחישים ──────────────────────────────────────────────
create table public.sim_scenarios (
  id            uuid primary key default gen_random_uuid(),
  slug          text not null,
  version       int  not null default 1,
  course_type   text not null check (course_type in ('practitioner','master')),
  module_id     int,
  lesson_id     int,
  title         text not null,
  primary_skill text not null,            -- 'chunk_down' | 'rapport' | 'meta_model' ...
  difficulty    int  not null check (difficulty between 1 and 3),
  turn_budget   int  not null default 12,
  spec          jsonb not null,           -- כל ההגדרה. סכמה ב-2.2
  is_published  boolean not null default false,
  created_at    timestamptz default now(),
  unique (slug, version)
);

-- ── סשנים ────────────────────────────────────────────────
create table public.sim_sessions (
  id              uuid primary key default gen_random_uuid(),
  user_id         uuid not null references auth.users(id) on delete cascade,
  scenario_id     uuid not null references public.sim_scenarios(id),
  scenario_version int not null,           -- קיפאון. תרחיש שהשתנה לא משנה סשן ישן
  status          text not null default 'in_session'
                  check (status in ('briefing','in_session','ended','debriefed')),
  outcome         text check (outcome in ('success','budget','collapse','abandoned')),
  metrics         jsonb not null,          -- מצב נוכחי. סכמה ב-2.3
  unlocked_facts  text[] not null default '{}',
  flags           jsonb not null default '{}',   -- מונים: advice_count, why_count ...
  rolling_summary text default '',
  turn_count      int not null default 0,
  started_at      timestamptz default now(),
  ended_at        timestamptz,
  debrief         jsonb,                   -- כרטיס הציון. סכמה ב-2.4
  tokens_in       int default 0,
  tokens_out      int default 0
);

-- ── תורות, append only ───────────────────────────────────
create table public.sim_turns (
  id             bigserial primary key,
  session_id     uuid not null references public.sim_sessions(id) on delete cascade,
  turn_index     int not null,
  student_text   text not null,
  patient_text   text not null,
  evaluation     jsonb not null,           -- פלט השופט. סכמה ב-2.5
  metrics_after  jsonb not null,
  latency_ms     int,
  created_at     timestamptz default now(),
  unique (session_id, turn_index)
);

create index on public.sim_sessions (user_id, started_at desc);
create index on public.sim_turns (session_id, turn_index);
```

**RLS, שלושתן:**

```sql
alter table public.sim_scenarios enable row level security;
alter table public.sim_sessions  enable row level security;
alter table public.sim_turns     enable row level security;

-- תרחישים: קריאה בלבד, רק מה שפורסם, רק למי שזכאי
create policy sim_scenarios_read on public.sim_scenarios
  for select to authenticated
  using (
    is_published
    and (
      course_type = 'practitioner'
      or exists (select 1 from public.profiles p
                 where p.id = auth.uid() and p.role in ('paid_customer','admin'))
    )
  );

-- סשנים: הבעלים קורא בלבד. כתיבה רק דרך service role בתוך Edge Function
create policy sim_sessions_read on public.sim_sessions
  for select to authenticated using (user_id = auth.uid());

create policy sim_turns_read on public.sim_turns
  for select to authenticated
  using (exists (select 1 from public.sim_sessions s
                 where s.id = session_id and s.user_id = auth.uid()));
```

⚠️ **אין שום policy של INSERT או UPDATE ל-`authenticated`.**
כל כתיבה עוברת ב-Edge Function עם service role.
לקוח שיכול לעדכן `metrics` יכול להכריז על עצמו מוצלח, והציון מאבד משמעות.
זה בדיוק הדפוס שכבר נאכף בפורטל, ואסור לסטות ממנו כאן.

⚠️ `spec` **לא** נחשף ללקוח כמו שהוא.
הדפדפן מקבל רק את `briefing` ואת השורה הפותחת, דרך RPC ייעודי.
`gated_facts` ו-`scoring_rules` שיושבים ב-JSON יידלפו ישירות ל-DevTools אם השורה נשלחת שלמה.

### 2.3 מדדי מצב מטופל

ארבעה מדדים, 0-100. לא שלושה ולא שישה.

| מדד | מה הוא מודד | עולה מ | יורד מ |
|-----|-------------|--------|--------|
| `rapport` | עד כמה היא מרגישה שרואים אותה | החזרה על המילים שלה, קצב תואם, שיקוף, הכלה | עצה, שיפוט, מונחים, קטיעה, "למה" |
| `resistance` | הגנתיות. **לא ההפך מראפור** | איתגור לפני זמנו, שאלה מכוונת, מסגור מוקדם | פירוק עדין כשהראפור גבוה, תיקוף |
| `emotional_depth` | כמה חומר אמיתי על השולחן | קצב רגשי, שאלה שנוגעת בחוויה | רציונליזציה, מעבר לפתרונות |
| `specificity` | **מדד היעד בתרחיש הזה.** כמה מההכללה פורקה | איתגור כמת כולל, שאלת התנהגות, זמן, מקום | הכללה נוספת מצד התלמיד |

`rapport` ו-`resistance` נעים בנפרד בכוונה.
אדם יכול לסמוך עליך ועדיין להיות מגונן, וזה בדיוק המקום שבו רוב התלמידים נשברים.

**כללי חישוב, בקוד ולא במודל:**
- כל מדד נחתך ל-`[0,100]`
- שינוי מקסימלי לתור: ±25 מצטבר. תור אחד לא הופך סשן
- רצפת התנגדות לפי קושי: קושי 1 רצפה 10, קושי 2 רצפה 25, קושי 3 רצפה 35. מונע קריסה לא מציאותית
- כל דלתא נרשמת ב-`sim_turns.evaluation` עם הסיבה שלה. מדד שקופץ בלי שורה מסבירה הוא באג, ואפשר יהיה להוכיח אותו

## 3. לוגיקת סוכן ה-AI

### 3.1 ההחלטה: שופט נפרד. כן

**לא לאחד.**
מודל אחד שגם משחק וגם שופט נכשל בשתי דרכים צפויות:

1. **דליפת שיפוט לתוך המשחק.** הוא יודע שהתלמיד צדק, ולכן המטופלת נפתחת יותר ממה שהמצב מצדיק. נוצר מטופל שמתגמל כוונה טובה במקום ניסוח מדויק.
2. **הטיית התחייבות.** כשהתגובה נכתבת לפני השיפוט, השיפוט מתיישר לתגובה שכבר נכתבה. הוא מנמק במקום לשפוט.

**החלוקה:**

| סוכן | תדירות | מודל | תפקיד | סמכות |
|------|--------|------|-------|-------|
| שופט-תור | כל תור | Haiku / Gemini Flash | סיווג המהלך + דלתאות. JSON בלבד | **סמכות בלעדית על המצב** |
| שחקן-מטופלת | כל תור | Sonnet | שורת דיאלוג אחת. טקסט בלבד | אפס סמכות. מקבל מצב כעובדה |
| מבקר-תחקיר | פעם בסוף | Sonnet | כרטיס ציון + ניסוחים חלופיים | סמכות על הפידבק, לא על המצב |

המהלך החכם כאן הוא שהשיפוט התכוף הוא **המשימה הקלה** (סיווג לתוך רשימה סגורה), ולכן הוא רץ על המודל הזול.
המשימה היקרה, לשחק בן אדם משכנע, רצה על החזק.
וההערכה האיכותית באמת קורית פעם אחת, בסוף, על כל התמליל.
12 קריאות זולות ועוד אחת טובה, במקום 12 קריאות יקרות.

**לפני שני המודלים יש שכבת קוד.**
מהלכים מובהקים מסווגים ב-regex בלי מודל בכלל: הודעה שמתחילה ב"למה", מונח מתוך רשימת ז'רגון סגורה, משפט ציווי שמתחיל ב"כדאי ש" או "תנסי".
זה חוסך קריאות, ובעיקר הופך את החוקים הכי חשובים ל**דטרמיניסטיים**.
תלמיד שכתב "למה" יקבל את אותה תגובה בכל פעם, וזה מה שמלמד.

**מסלול חסכוני, אם רוצים לחתוך עלות ב-40%:** קריאה אחת שמחזירה מבנה שבו שדה `evaluation` **חייב להופיע לפני** שדה `reply`.
סדר השדות כופה שיפוט לפני תגובה ומחזיר רוב הערך.
החיסרון האמיתי: אי אפשר לשלוח את השיפוט למודל זול, והוא נשאר על היקר.
**המלצה: להתחיל בשתי קריאות.** לעבור לאחת רק אם המדידה תראה שהעלות מציקה.

### 3.4 אנטי-קריסה

שלוש שכבות נגד המטופלת שנשברת מהר מדי:

1. **רצפת התנגדות לפי קושי.** לא יורדת מתחת לרצפה בלי מהלך מסווג ומזכה
2. **עובדה נפתחת רק דרך הקוד.** השחקן פיזית לא מחזיק טקסט שלא נפתח, לכן הוא לא יכול לדלוף אותו
3. **בלם קצב.** לכל היותר עובדה אחת נפתחת בתור. שני מהלכים מצוינים ברצף פותחים אחת עכשיו ואחת בתור הבא

### 3.5 בטיחות מקצועית

הסימולטור מדמה חדר טיפול, ולכן שלושה גבולות שנכנסים לקוד ולא לשיקול דעת:

- **תרחישים שאסור לכתוב:** אובדנות, פגיעה עצמית, טראומה חריפה, קטינים בסיכון. סימולטור אינו המקום ללמוד את אלה
- **בלם לתלמיד.** אם התלמיד כותב על עצמו מצוקה אמיתית, הסשן נעצר והמסך עובר להודעת אנוש עם דרך יצירת קשר. זיהוי במילות מפתח בקוד, לא בשיקול דעת של מודל
- **כתב ויתור קבוע בחדר ההכנה:** זה תרגול, לא הדרכה קלינית, ולא תחליף למטופל אמיתי תחת סופרוויז'ן

## 5. בנייה בשלבים

| שלב | מה נבנה | תוצר שאפשר למדוד |
|-----|---------|------------------|
| 1 | שלוש הטבלאות + RLS + תרחיש הזהב בתוך `sim_scenarios` | שאילתה מחזירה תרחיש, לומד רגיל מקבל 403 על סשן של אחר |
| 2 | `sim-turn` עם שופט + שחקן, בלי UI. בדיקה ב-curl | 10 מסלולי בדיקה קבועים מחזירים סיווג יציב |
| 3 | UI בתוך `nlp-game-master.html`: חדר הכנה, צ'אט, מדי-מצב | הלל מריץ סשן שלם בטלפון |
| 4 | `sim-debrief` + כרטיס ציון + "שחק שוב מתור N" | תחקיר אמיתי על סשן אמיתי |
| 5 | XP ללוח המובילים + מכסה יומית + תקרת ₪ | סשן שלישי ביום נחסם, לוח מעודכן |
| 6 | שני תרחישים נוספים לאותה מיומנות, רק אז מיומנות שנייה | וריאציה מונעת שינון של התסריט |

**למדוד לפני שמרחיבים** (משתמש חי, לא הערכה):
- עלות ממוצעת לסשן מול ה-₪0.24 שחושב כאן
- אחוז תורות עם `confidence < 0.5`. גבוה מ-15% פירושו שהרשימה הסגורה לא מפרידה מספיק טוב
- אחוז סשנים שנגמרים בקריסת ראפור. מעל 40% והקושי לא מכויל
- כמה תלמידים לוחצים "שחק שוב". זה המדד היחיד שאומר אם זה באמת מלמד

## 6. הסיכונים האמיתיים

1. **התרחיש יישחק פעם אחת.** מטופלת עם תסריט ידוע היא חידה, וחידה פותרים רק פעם אחת. ההגנה היא שלושה וריאנטים לכל מיומנות עם שמות, הקשרים ומכשולים שונים, בצירוף אתחול מדדים אקראי בטווח ±10
2. **השופט יסווג לא נכון והתלמיד יראה עוול.** לכן `confidence`, לכן חצי דלתא בספק, ולכן כפתור "אני חולק" בתחקיר שנרשם לטבלה ומשמש לכיול
3. **העלות תזחל דרך אורך השיחה.** החלון החסום הוא ההגנה, ויש לאמת אותה בפועל על סשן של 14 תורות ולא להניח אותה
4. **תרחיש כתוב גרוע יהרוס את האמון בכלי.** `gated_facts` ו-`known_errors` הם כתיבה מקצועית של רם, לא של מודל. זה התוכן, לא העטיפה
